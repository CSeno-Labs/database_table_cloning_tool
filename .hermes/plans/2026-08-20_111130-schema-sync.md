# sync-db Schema Sync Implementation Plan

**Goal:** adicionar sincronização explícita de estrutura/schema ao `sync-db`, separada da sincronização de dados, com fluxo interativo claro e comandos não interativos previsíveis.

**Contexto decidido com Neto:**
- Backup deve ser opcional, não sugerido dentro dos fluxos interativos de sincronização.
- O menu principal já terá uma opção separada de backup; isso é suficiente.
- Schema sync deve ser explícito; `sync-db sync` não deve alterar estrutura automaticamente sem escolha clara do usuário.
- Recriação de tabela existirá, mas precisa ser explícita, sem alias.

---

## UX final definida

### Menu principal

Adicionar opção dedicada:

```text
1 - Sincronizar tabelas
2 - Sincronização avançada
3 - Estrutura das tabelas
4 - Backup de tabelas
5 - Bancos / conexões
6 - Logs
7 - Mais
8 - Sair
```

Remover sugestões/pedidos de backup dos fluxos interativos de sync. O usuário acessa backup pelo menu dedicado ou via flags explícitas de comando.

### Menu de estrutura

```text
Estrutura das tabelas

Modelo: prod
Banco que será alterado: local
Tabelas: aluno, periodo

1 - Ver diferenças

2 - Correção básica
    Adiciona apenas colunas faltantes

3 - Adicionar itens faltantes
    Você escolhe colunas, índices e chaves
    Não altera nem remove o que já existe

4 - Copiar estrutura
    Usa ALTER TABLE para deixar igual à origem
    Pode alterar e remover itens existentes

5 - Recriar tabela a partir da origem
    Substitui a tabela por uma nova com a estrutura da origem
    Backup é opcional

6 - Voltar
```

## Comandos finais

```bash
sync-db schema diff -t aluno -o prod -d local
sync-db schema copy -t aluno -o prod -d local
sync-db schema update -t aluno -o prod -d local
sync-db schema recreate-table -t aluno -o prod -d local
```

### Ações

```text
diff
  Mostra diferenças sem alterar nada.

copy
  Copia estrutura da origem para o destino via ALTER TABLE.
  Pode adicionar, alterar e remover extras.
  Objetivo: destino igual à origem.

update
  Atualiza o destino com a estrutura da origem via ALTER TABLE.
  Pode adicionar e alterar divergentes.
  Não remove itens que existem só no destino.

recreate-table
  Recria tabela no destino com estrutura da origem.
  Sem alias.
  Backup opcional.
```

Não usar --mode, --include nem aliases curtos nesta versão simplificada.

---

## Regras de backup

- Backup não deve aparecer como sugestão dentro dos fluxos interativos de sincronização de dados.
- Backup continua disponível por comando e menu separado.
- Em `schema recreate-table`, backup deve ser opcional, não obrigatório.
- Se houver backup, usar mecanismo explícito já existente ou reaproveitar helpers do projeto.
- Para operações destrutivas sem backup, exigir confirmação forte no modo interativo.

## Estratégia técnica

### Fase 1 — infraestrutura de schema diff/plano interno

1. Criar módulo de inspeção de schema, provavelmente `src/syncdb/schema.py`.
2. Ler metadados via `information_schema` e/ou `SHOW CREATE TABLE`.
3. Representar diferenças por categoria:
   - colunas;
   - índices;
   - chaves primárias/únicas;
   - chaves estrangeiras;
   - engine/charset/collation.
4. Gerar plano de operações sem aplicar.
5. Criar testes unitários puros para normalização de ações e planejamento.

### Fase 2 — comandos CLI mínimos

1. Adicionar subcomando `schema` em `src/syncdb/cli.py`.
2. Adicionar ações `diff`, `copy`, `update`, `recreate-table`.
3. Inicialmente implementar o esqueleto das ações como primeira entrega verificável.
4. Implementar validação: ações explícitas sem aliases curtos e sem `--mode`/`--include`.

### Fase 3 — apply via ALTER

1. Implementar `schema copy` via ALTER, não DROP TABLE.
2. Implementar `schema update` via ALTER preservando extras.
4. Parar com erro claro quando operação automática segura não for suportada.

### Fase 4 — recreate-table

1. Implementar modo explícito `recreate-table`.
2. Usar fluxo seguro com tabela temporária/rename quando possível, não `DROP TABLE` direto como primeira ação.
3. Backup opcional.
4. Exigir confirmação forte.
5. Bloquear aliases.

### Fase 5 — integração interativa e preflight no sync de dados

1. Adicionar menu “Estrutura das tabelas”.
2. Quando sync de dados detectar diferença de estrutura, no interativo mostrar opções seguras.
3. No modo comando direto, falhar por padrão e sugerir comandos `schema diff`/`schema sync`.
4. Remover sugestões de backup dos fluxos interativos de sync.
